# `export_viewer_data.py` — 3D WebGIS Exporter Guide

Exports a viewer-compatible GeoJSON from frustum volumetric analysis outputs and deploys the static 3D CesiumJS visualizer.

> [!IMPORTANT]
> **Run `calculate_frustum_volume.py` first.**  
> This script reads the slice shapefiles, cumulative polygons, and CSV reports generated by the volumetric calculation engine. If those outputs are missing, the exporter halts with a diagnostic error message.

---

## Prerequisites

Before running the viewer exporter, ensure your volumetric analysis output directory contains:

```
outputs/<dataset_name>/
  ├── <prefix>_frustum_slice_polygons.shp       ← required (horizontal slices)
  ├── <prefix>_frustum_cumulative_polygons.shp  ← required (cumulative solid stages)
  └── <prefix>_frustum_volumetric_report.csv    ← required (tabular schedule)
```

---

## Basic Usage

```bash
# Export 3D viewer data for any contour shapefile
python scripts/export_viewer_data.py --input examples/sample_heap_south/Contours.shp
```

The script automatically derives the output directory and filename prefix from the input path:

| Input Path | Derived Output Directory | Derived Prefix |
| :--- | :--- | :--- |
| `examples/sample_heap_south/Contours.shp` | `outputs/sample_heap_south/` | `contours` |
| `inputs/heap_corridor/elev_contours.shp` | `outputs/heap_corridor/` | `elev_contours` |

---

## Generated Deliverables

Two deliverables are generated in `outputs/<dataset_name>/`:

| File | Description |
| :--- | :--- |
| `viewer_data.geojson` | Compact GeoJSON payload containing hollow slice polygons, solid cumulative stages, and original contour line strings. |
| `<prefix>_3d_viewer.html` | Standalone, zero-CORS CesiumJS WebGIS application. |

---

## Opening and Viewing the 3D Model

The viewer uses `fetch()` to load `viewer_data.geojson`. Modern web browsers require a local HTTP server to serve local files:

```bash
# Start a lightweight local server
python3 -m http.server 8080 --directory outputs/sample_heap_south/

# Open in your web browser:
# http://localhost:8080/contours_3d_viewer.html
```

## Required Shapefile Columns

By default, the script expects standard column names produced by `calculate_frustum_volume.py`:

| CLI Flag | Default Name | Description |
| :--- | :--- | :--- |
| `--col-stage` | `STAGE_ID` | Integer stage / layer ID |
| `--col-z-low` | `Z_LOW` | Bottom elevation of slice (m) |
| `--col-z-high` | `Z_HIGH` | Top elevation of slice (m) |
| `--col-delta-h` | `DELTA_H` | Vertical interval $\Delta h$ (m) |
| `--col-area` | `AREA_M2` | Planimetric slice area ($\text{m}^2$) |
| `--col-vol` | `VOL_M3` | Frustum slice volume ($\text{m}^3$) |
| `--col-vol-cuft` | `VOL_CUFT` | Frustum slice volume ($\text{ft}^3$) |
| `--col-cumul` | `CUMUL_M3` | Cumulative volume ($\text{m}^3$) |
| `--col-cum-cuft` | `CUM_CUFT` | Cumulative volume ($\text{ft}^3$) |
| `--col-elev` | `ELEVATION` | Contour elevation value (m) in input survey |

> [!NOTE]
> If any expected column name differs in a third-party shapefile, the script stops immediately and displays all available columns in the file without silent fallbacks.

---

## CLI Mapping Examples

If your custom shapefile uses alternative column names (e.g. `A_LOW_M2` instead of `AREA_M2`), pass the appropriate CLI override flag:

```bash
python scripts/export_viewer_data.py \
  --input path/to/custom_contours.shp \
  --col-area A_LOW_M2 \
  --col-elev Z
```

## Full End-to-End Workflow

```bash
# Step 1: Calculate volumetric quantities & generate GIS shapefiles
python scripts/calculate_frustum_volume.py --input examples/sample_heap_south/Contours.shp

# Step 2: Export 3D WebGIS GeoJSON & deploy viewer
python scripts/export_viewer_data.py --input examples/sample_heap_south/Contours.shp

# Step 3: Serve locally and inspect
python3 -m http.server 8080 --directory outputs/sample_heap_south/
# Navigate to http://localhost:8080/contours_3d_viewer.html
```
